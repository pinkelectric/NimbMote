# Bentley Remote v0.2.0 — LAN pairing threat review

## Что защищено

- Bootstrap discovery отвечает только в явно открытом на Windows 10-минутном
  окне. Probe/response привязаны к коду, timestamp, nonce, identity и UDP
  endpoint; повтор nonce отклоняется.
- UDP не содержит pairing secret. Адрес кандидата берётся только из source
  endpoint ответа, а окончательное сопряжение проверяет тот же шестизначный код.
- Новый 32-байтный secret передаётся через ephemeral ECDH P-256, HKDF-SHA256 и
  AES-256-GCM с аутентифицированным transcript. Secret хранится Android
  Keystore/SharedPreferences и Windows DPAPI так же, как в v0.1.1.
- Paired discovery подписан сохранённым secret и identity. WebSocket-кандидат
  становится active только после текущей взаимной HMAC-аутентификации.
- `system.action` принимает только `lock`, `sleep`, `restart`, `shutdown`; путь,
  shell-строка и аргументы с Android не принимаются.

## Остаточные риски v0.2.0

- Это не PAKE. Шестизначный код имеет около 20 бит энтропии; захваченный code
  proof допускает offline-перебор. Короткое окно снижает online-риск, но не
  превращает код в высокоэнтропийный пароль.
- После handshake основной канал остаётся `ws://`: payload не зашифрован и не
  имеет отдельного MAC на каждое сообщение. HMAC аутентифицирует стороны при
  подключении, но не обеспечивает TLS-свойства для всей сессии.
- Имена/metadata Windows могут быть видны пассивному наблюдателю общей сети;
  противник с возможностью вмешательства в TCP находится вне модели доверенной
  LAN этой тестовой версии.

## Практическое правило

Использовать v0.2.0 только в собственной домашней Wi-Fi/LAN или личном hotspot.
Не выполнять pairing и power actions в публичной/гостевой сети. Для публичных
сетей следующая security-итерация должна добавить PAKE либо QR с
высокоэнтропийным bootstrap key и TLS/AEAD-защиту всего канала.
